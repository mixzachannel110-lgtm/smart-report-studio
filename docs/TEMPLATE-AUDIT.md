# Template Fidelity Audit — PDF ต้นฉบับทั้งสองฉบับ

ตรวจวันที่ 29 ตุลาคม 2569 โดยทีมตรวจสอบ Template สำหรับ IDC Smart Report Studio

## ขอบเขตและหลักฐาน

- Template A: `PM.FP.69-151 ครัวการบินกรุงเทพ-เชียงใหม่ 1-1 2569 .pdf` จำนวน 56 หน้า
- Template B: `PMFP69~1.PDF` หรือ PM.FP.69-095, AGC Micro Glass โรง C จำนวน 44 หน้า
- อ่านข้อความจาก PDFKit ใน `source-1.txt` / `source-2.txt` และตรวจภาพหน้าปก หน้า Checklist หน้า Flow และหน้าสแกนท้ายเล่มจาก PDF ต้นฉบับ
- ตรวจ MediaBox ด้วย PDFKit และทวนขนาดทุกหน้าจาก Native Geometry ใน `dist/assets/templates/source-layout.json` ไม่ได้อนุมานขนาดกระดาษจากชื่อเอกสาร; การสรุปรอบแรกว่าเป็น Letter ทุกหน้าคลาดเคลื่อนที่หน้าสแกน AGC 37–43 และแก้ไขแล้วในฉบับนี้
- ไม่ได้แก้ไขไฟล์ PDF ต้นฉบับ รายงานนี้เป็นรายการตรวจสำหรับพัฒนาและรับงาน ไม่ใช่การยืนยันว่าระบบปัจจุบันสร้างเอกสารเหมือนต้นฉบับแล้ว

## สิ่งที่ต้องแก้จากแนวทาง A4/Modern Report เดิม

PDF ทั้งสองมีหน้าหลักเป็น **US Letter 612 × 792 pt หรือ 8.5 × 11 นิ้ว** อัตราส่วน Portrait คือ `612 / 792` และ Landscape คือ `792 / 612` แต่ Template B มีหน้าสแกน A4 แทรก จึงต้องกำหนดขนาดแบบรายหน้า ไม่ใช้ Page Size เดียวทั้งเล่ม

- Template A หน้า 43 เป็น Landscape Letter
- Template B หน้า 25 เป็น Landscape Letter
- Template A: 55 หน้า Portrait Letter และ 1 หน้า Landscape Letter (หน้า 43)
- Template B: หน้า 1–24, 26–36 และ 44 เป็น Portrait Letter รวม 36 หน้า; หน้า 25 เป็น Landscape Letter; **หน้า 37–43 เป็น Portrait A4 ขนาด Native 595.2 × 841.67999 pt** รวม 7 หน้า
- หลักฐาน Machine-readable: `source-layout.json` กลุ่ม `pm151.pages` และ `pt095.pages`, index เริ่ม 0; ขนาดหน้าอยู่ที่ `width` / `height`
- การยืดหน้า Letter ให้เต็ม A4 ทำให้สัดส่วนตัวอักษร กรอบ และภาพผิดต้นฉบับ หากต้องส่ง A4 ต้อง Fit Uniformly และยอมรับขอบเพิ่มเติมอย่างชัดเจน

รายงานตัวอย่างหน้าปกไม่มีภาพเครื่องยนต์ขนาดใหญ่ ภาพเครื่องยนต์อยู่ในเนื้อหา การใส่ภาพเครื่องยนต์ในปกสไตล์ Modern จึงไม่ผ่านเงื่อนไข “เหมือนต้นฉบับ”

## Design Fingerprint

### หน้าปก

- พื้นขาว ไม่ใช้ Navy Banner ไม่ใช้ Hero Photo
- รูปทรงสีแดงขวาบนและเทาขวาล่าง สัดส่วนรูปทรงของสองฉบับต่างกัน ควรเก็บเป็น Asset/Template คนละชุด
- ชื่อรายงานสีดำด้านซ้าย 2 บรรทัด: `Fire Pump System` / `Preventive Maintenance` หรือ `Performance Test`
- ชื่อลูกค้าภาษาไทยบรรทัดด้านล่าง ต้องรักษาความกว้างและตำแหน่ง ไม่ให้ล้นเข้าแถบสี
- เครื่องหมาย Pakorn และชื่ออังกฤษ `PAKORN TECHNICAL SUPPLY LIMITED PARTNERSHIP` อยู่ช่วงล่างซ้าย
- รหัสรายงานอยู่ล่างขวา มีตำแหน่งต่างจากหน้าภายใน

### หน้าภายใน

- โลโก้ Pakorn Technical Supply แบบเต็มอยู่ซ้ายบน
- Header ขวาเป็นข้อความรายงานภาษาอังกฤษแบบ Bold Italic และชื่อลูกค้าภาษาไทย
- เส้นแดงบางเต็มแนวใต้ Header
- ชื่อหมวด/หัวข้อตัวหนาสีดำ ตำแหน่งกึ่งกลางตามต้นฉบับ
- ตารางเส้นดำบาง Header สีส้มอ่อน (ใกล้ `#F4B183`; ต้องอ่านสีจากต้นฉบับจริงเพื่อ Lock Token) ไม่ใช้หัวตารางน้ำเงิน
- ตาราง Checklist มีคอลัมน์ลำดับ / รายการ / ผล / หมายเหตุ พร้อม Legend Y/N/None ที่ด้านล่าง
- ผล `None` เดิมคือ “ไม่ได้ติดตั้ง” ไม่ควรแปลรวมเป็น “ไม่เกี่ยวข้อง” หรือ “ไม่ได้ตรวจ”
- หมายเลขหน้าอยู่กลางล่าง และรหัสงานอยู่ขวาล่าง ไม่ใช้ Footer แบบ IDC Studio
- รูปในช่องต้องรักษาอัตราส่วนและส่วนหลักฐานที่สำคัญ เปลี่ยนรูปใหม่ภายในกรอบเดิม ไม่ยืดหรือ Crop โดยอัตโนมัติจนตัวเลข/ป้ายหาย

### ฟอนต์ที่ตรวจได้จาก PDF A

อ่าน `/BaseFont` ได้ชื่อฟอนต์หลัก `AngsanaUPC` Regular/Bold/BoldItalic/Italic, `AgencyFB-Bold`, `CordiaNew-Bold`, `BrowalliaNew`/Bold, `Calibri`, `ArialMT`, `Wingdings`, `Wingdings2` และ `CambriaMath`

นี่คือรายชื่อ Embedded Font Resources ไม่ใช่การยืนยันว่าฟอนต์ใดใช้กับทุกตำแหน่ง ต้องจับคู่ตาม Page Resources/Text Runs อีกครั้งก่อน Pixel-level Acceptance ไม่ควรใช้ IBM Plex หรือ Manrope แทนทั้งหมดในเนื้อรายงานหากต้องการเหมือนต้นฉบับ พื้นที่ UI เว็บสามารถใช้ฟอนต์ UI เดิมได้

การนำ Embedded Subset Font มาใช้บนเว็บต้องตรวจสิทธิ์และความครบของ Glyph ก่อน ไม่ควรถือว่า Font Subset ที่มีในงานเดิมรองรับชื่อลูกค้าใหม่ทุกตัว

## ข้อมูลที่ต้องล้างเมื่อสร้างงานใหม่

| ชนิดข้อมูล | นำมาใช้ซ้ำได้หรือไม่ | พฤติกรรมที่ต้องมี |
|---|---|---|
| โครงสร้างหน้า โลโก้ กรอบ สี ชื่อหัวข้อ | ได้ | Versioned Template |
| ลูกค้า ที่อยู่ Site และข้อมูล Asset | ได้หลังเลือกงานเดิม | ให้ตรวจยืนยันว่าข้อมูลยังปัจจุบัน |
| ผล Y/N/None หมายเหตุ และค่าตรวจ | ไม่ใช้เป็นผลใหม่ | เริ่มว่าง/รอตรวจ ไม่ตั้ง Y โดยอัตโนมัติ |
| ภาพหน้างาน/ค่ามาตรวัดเก่า | ไม่แนบเป็นหลักฐานใหม่อัตโนมัติ | คงไว้ใน Historical Reference เท่านั้น |
| กราฟและผล Pass/Fail/Inconclusive เก่า | ไม่ได้ | สร้างใหม่จากค่าจริงและ Rule Version ที่ยืนยัน |
| ข้อบกพร่องและข้อเสนอแนะเฉพาะงาน | ไม่ได้โดยตรง | แสดงเป็นประวัติเพื่อให้ตรวจซ้ำ ไม่ยืนยันว่าเกิดในงานใหม่ |
| Calibration Certificate | เสนอใช้ซ้ำได้แบบมีเงื่อนไข | ยืนยันว่าเป็นเครื่องมือที่ใช้จริงและยังอยู่ในช่วงใช้งานที่ยอมรับ |
| หนังสือรับรอง ลายเซ็น พยาน ตรารับรองสำเนา | ไม่ได้ | ใช้ Blank Form และลงนามเฉพาะงานใหม่ตามสิทธิ์ |
| ใบอนุญาต/ใบอบรมบุคคล | แนบได้เมื่อได้รับอนุญาตและยังถูกต้อง | ไม่คัดลอกลายเซ็นรับรองสำเนาเก่ามารับรองงานใหม่ |
| กระดาษ Field Record กรอกลายมือ | ไม่ได้ | แนบสแกนของงานใหม่หรือสร้างแบบเปล่าที่กรอกข้อมูลใหม่ |

คำถามที่ระบบต้องให้ผู้ใช้ยืนยันเมื่อเลือก “สร้างจากงานเดิม” ได้แก่ ลูกค้า/ที่อยู่ยังเดิมหรือไม่, อุปกรณ์/Serial ยังตรงหรือไม่, เครื่องมือใดใช้ตรวจจริง, Certificate ใดใช้กับงานนี้ได้, ใครมีอำนาจรับรอง และมีเอกสารงานใหม่ใดต้องอัปโหลด ทั้งหมดเป็นการยืนยันข้อมูลใน Workflow ไม่ใช่การขอสิทธิ์ให้ระบบเริ่มพัฒนาต่อ

## Data Fidelity Cases

1. ครัวการบิน หน้า 44 แสดงหัวจุด 99.2% และตาราง Nominal 750 GPM ขณะที่คำอธิบายหน้า 45 ระบุ Actual Flow สูงสุด 744 GPM ต้องเก็บ Nominal/Actual แยกและชี้ความคลาดเคลื่อนให้ตรวจ ห้ามเปลี่ยนค่าทุกช่องเป็น 750 เงียบ ๆ
2. ครัวการบิน 150% ทดสอบไม่ได้ ช่องตารางต้องเป็นข้อความ/ขีด และกราฟไม่มีจุดวัด ไม่สร้าง 0 PSI แทน
3. ครัวการบิน 116 / 86 PSI และ Suction บางช่องเป็นขีด ต้องไม่เปลี่ยนขีดเป็นศูนย์โดยอนุมาน
4. AGC Discharge 150 / 135 / 115 และ Suction 0 / -6 / -10 ต้องคงค่าติดลบได้
5. AGC Nameplate ไม่มีค่า 0%/150% บางรายการ ต้องแสดงไม่สามารถสรุปผลในเกณฑ์ที่ขาดข้อมูล ไม่สรุป “ผ่านทั้งหมด”
6. กราฟต้นฉบับใช้ `%GPM` บนแกน X หากใช้ Actual GPM ในหน้ากรอกเพื่อความชัดเจน ต้องมี renderer สำหรับกราฟรายงานเดิมแยก ไม่เปลี่ยนแกนต้นฉบับโดยไม่ระบุ
7. แม้ Template B ปกเรียก Performance Test แต่ Header ภายในต้นฉบับเรียก Preventive Maintenance การแก้ให้เป็นชื่อเดียวกันทุกหน้าคือการปรับเนื้อหา ไม่ใช่การทำสำเนารูปแบบให้เหมือน ต้องแสดงการตัดสินใจนี้อย่างชัดเจน

## Fidelity Acceptance Checklist

### ตรวจรูปแบบ

- [ ] เลือกสอง Template ได้แยกกันและแสดงชื่อไฟล์อ้างอิงที่ถูกต้อง
- [ ] ขนาด Letter Portrait/Landscape และ A4 ของ AGC หน้า 37–43 ตรง Native Geometry รายหน้า PDF จริง
- [ ] หน้า Cover ของแต่ละชุดใช้รูปทรง สี โลโก้ ตำแหน่งชื่อ และ Footer ของชุดนั้น
- [ ] ไม่มีภาพ Hero/หัวตารางน้ำเงิน/IDC Branding แทรกในตัวรายงานเดิม
- [ ] หน้า Header/Footer, หมายเลขหน้า, Report No ตรงตำแหน่งและไม่ถูก Clip
- [ ] ฟอนต์ไทย วรรณยุกต์ ขนาดน้ำหนัก และ Line Height ตรวจด้วยภาพจริง
- [ ] ความกว้างคอลัมน์ สีหัวตาราง เส้นกรอบ และ Legend ตรงต้นฉบับ
- [ ] หน้า Landscape ไม่ถูกหมุนหรือย่อจนอ่านหลักฐานไม่ได้
- [ ] ปกหลังของทั้งสองชุดแสดงข้อมูลและตำแหน่งตามต้นฉบับ

### ตรวจการทำงาน

- [ ] แยกชัดเจนระหว่าง “ดูต้นฉบับ” กับ “รายงานใหม่จากข้อมูลที่กรอก”
- [ ] เปลี่ยนลูกค้า/ที่อยู่/วันที่/Report No แล้วทุกตำแหน่งที่เกี่ยวข้องเปลี่ยน ไม่มีข้อความเก่าซ่อนอยู่ใต้ Overlay
- [ ] เปลี่ยนคำตอบแล้วผลและหมายเหตุในตารางถูกต้อง ไม่ทับข้อความเดิม
- [ ] เลือกรูปใหม่แล้วแทนกรอบภาพเดิมได้จริง มี Caption/Source Mapping และเก็บต้นฉบับ
- [ ] ตารางและกราฟมาจากค่าชุดเดียวกัน ข้อความสรุปไม่ขัดกับค่าตรวจ
- [ ] ภาคผนวกใช้ไฟล์ที่เลือกของงานนี้ ไม่คัดลอกเอกสารรับรองเดิมอัตโนมัติ
- [ ] รายงานใหม่ไม่มีลายเซ็นหรือการรับรองของงานเก่า
- [ ] PDF Export เทียบกับ Preview และตรวจทุกหน้าที่มี Dynamic Binding
- [ ] การบันทึกเป็น PDF ไม่เพิ่ม Browser Header/Footer หรือขอบพิมพ์ที่เปลี่ยนสัดส่วน
- [ ] ข้อมูลยาว/จำนวนรูปเพิ่มมี Overflow Handling และสารบัญ/เลขหน้าใหม่ ไม่ตัดเนื้อหาทิ้ง

### วิธีตรวจภาพ

1. สร้าง Golden Reference ของแต่ละหน้าจาก PDF ที่ความละเอียดเดียวกัน
2. Render Output ที่ Page Box และ Scale เดียวกัน ปิด Browser Printing Header/Footer
3. เปรียบเทียบ Overlay/Diff เฉพาะส่วน Fixed Layout แยกออกจากข้อมูล Dynamic ที่ตั้งใจเปลี่ยน
4. บันทึก Pass/Fail รายหน้า ห้ามสรุป Pixel-perfect ทั้งเล่มจากการตรวจเพียงปก
5. ตรวจ Text Search และเปิดดูข้อมูลใต้ Overlay ด้วย เพื่อป้องกัน “หน้าตาดูเหมือนใหม่ แต่ยังมีข้อมูลเก่าซ่อนอยู่ใน PDF”

## ข้อจำกัดและการรายงานผลอย่างตรงไปตรงมา

- ใช้ภาพ PDF ทั้งหน้าจะทำให้ Reference Viewer เหมือนต้นฉบับ แต่ไม่ทำให้หน้านั้นเป็น Editable Template โดยอัตโนมัติ
- ใช้หน้า PDF เป็นพื้นหลังแล้ว Overlay ต้องล้าง/Redact ค่าเดิมจริง และป้องกันข้อความเก่าที่ถูก Search/Copy ได้ การปิดทับด้วยสี่เหลี่ยมอย่างเดียวอาจยังมีข้อมูลในไฟล์
- มีเพียงบางหน้าที่สร้างเป็น Editable แล้ว ต้องแสดงจำนวนหน้า/หัวข้อที่รองรับจริง และให้หน้าที่เหลือเป็น Reference อย่างชัดเจน
- จำนวน 56/44 หน้าเป็นจำนวนของ Golden Source เดิม งานใหม่อาจมีภาคผนวกและผลตรวจจำนวนต่างกัน การรักษารูปแบบไม่ควรบังคับแนบเอกสารเก่าให้ครบหน้า
- การตรวจฟอนต์และภาพที่นี่ใช้ PDFKit และภาพจากต้นฉบับ ไม่ได้ยืนยัน Browser Rendering หรือ PDF Export ของแอปปัจจุบัน
- รูป/ลายเซ็น/ใบอนุญาตใน AGC เป็นข้อมูลเดิมเฉพาะงาน ต้องควบคุมการใช้เป็นเอกสารอ้างอิง ไม่ใช้รับรองงานใหม่โดยอัตโนมัติ
